# Axiom libraries

Import with `import "lib/<path>" as <name>;`, for example
`import "lib/encoding/csv" as csv;`. These are the libraries released with the
[standard library](../std/README.md) (`std/`, the core): `lib/` is the directory beside
`std/`, in a release and in the source tree (spec §4.1). They may import the core and each
other; the core never imports them. Each is tested, and the parsers fuzzed, as before;
the core's rules (every public item documented, overflow trapping in tests) are adopted
here module by module. Media (`graphics/`, `audio/`, and the windows, controllers and
platform bindings under `os/`) are here too. The conventions of the core
([`std/README.md`](../std/README.md#conventions)) hold here as well.

The AAC decoder (`audio/aac.ax` and `audio/internal/aac/`) keeps its own license, the
LGPL 2.1 or later (`audio/internal/aac/LICENSE`); a program includes it only by importing
`lib/audio/aac`. Everything else here is MIT OR Apache-2.0, as the rest of the repository.

| [`os/objc`](os/objc.ax) | macOS only: the Objective-C runtime. `class`, `sel`, messages (`send`…`send6`, `call`, `send_f64`, `send_dd`, `send_dddd`, or a cast of `msg_send()` to the method's type), `string`/`string_of` (NSString), `number`, struct-valued properties by key-value coding (`get_struct`, `get_f64x2`, `get_f64x4`), autorelease pools, `retain`/`release`, `framework` (load one by name), classes made at run time whose methods are Axiom functions (`define_class`, `add_method`, `add_ivar`, `register_class`) |
| [`os/cocoa`](os/cocoa.ax) | macOS only: an AppKit `Window` with lib/os/win32's interface (`open` in points, `size` in pixels, `scale`, `set_title`, `handle` for Metal, `next_event` with the same `EventKind`s and Windows' virtual-key codes); a regular app with a Quit menu (Command-Q and the close button come as `CLOSE`), and menus of its own (`add_menu`, `add_item`, `add_separator`, `APP_MENU`; `MENU` events); a file-open dialog (`open_file`) |
| [`os/gamecontroller`](os/gamecontroller.ax) | macOS only: game controllers (Apple's GameController: Xbox, PlayStation, Switch Pro, MFi) with lib/os/xinput's interface: `state`, `Pad`, `vibrate` (Core Haptics), `battery`, `Tracker`, `name` |
| [`os/window`](os/window.ax) | A desktop `Window` on Windows (win32) and macOS (cocoa), chosen at run time: one interface and key codes for both, menus and the file-open dialog included |
| [`os/gamepad`](os/gamepad.ax) | Game controllers on Windows (xinput) and macOS (gamecontroller), chosen at run time |
| [`os/com`](os/com.ax) | Windows only: calling COM interfaces (`method` by vtable index, `release`, `query`, `init`), little-endian struct fields (`put32`, `get64`, ...), `utf16` |

## What the test suite covers

Every module has `test` blocks that the suite runs on WebAssembly and natively, except
those that need a device: the windows, GPUs, sound output and controllers (`os/window`,
`os/gamepad`, `audio/output`, `graphics/gpu`) and their backends (`os/win32`,
`os/cocoa`, `os/objc`, `os/com`, `os/xinput`, `os/gamecontroller`, `graphics/d3d11`,
`graphics/d3d12`, `graphics/d2d`, `graphics/hlsl`, `graphics/metal`,
`graphics/quartz`, `audio/xaudio2`, `audio/coreaudio`). The suite's macOS and Windows
sections build them and the examples that use them for their platforms and inspect the
binaries; running them is a manual check on a machine with the device. The codec
internals under `graphics/image/av1`, `graphics/image/webp`, `audio/opus`, `audio/aac`
and `graphics/shape` are tested through their parents against reference decoders and
shapers (the generators in `cmd/axiom/internal/tests/tools/` make those tests), and the
parsers are fuzzed (`docs/security.md`).
